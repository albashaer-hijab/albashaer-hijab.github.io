# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Marketing website (Arabic, RTL) for "حجابات البشائر" (Al-Basha'er), a Syrian scarf/hijab manufacturer. Next.js (App Router) + TypeScript + Tailwind CSS 4. Three pages (home, about, contact) plus `app/not-found.tsx`. No backend, database, or tests.

`AGENTS.md` warns that this Next.js version (16.x) has breaking changes: read the relevant guide in `node_modules/next/dist/docs/` before writing Next-specific code.

## Commands

```bash
npm run dev            # dev server at http://localhost:3000
npm run build          # production build (also runs type checking)
npm run lint           # eslint
npx tsc --noEmit       # standalone typecheck
```

There is no test runner. Verification is `lint` + `tsc` + `build`.

- Don't run `npm run build` while `npm run dev` is running: they share `.next/` and the dev server then serves stale or broken CSS. If that happens, stop the server, delete `.next`, restart.
- Next refuses a second `next dev` in the same folder; if one is already running on :3000, use it.
- `LayoutProps` (used in `app/layout.tsx`) is a global type generated by Next during `dev`/`build`; `tsc` fails on a fresh checkout until one of them has run.
- Replacing a file under `public/images/lifestyle/` with the same name may keep showing the old picture: delete `.next/cache/images` and hard-refresh.

## Deployment

Hosted on GitHub Pages at https://albashaer-hijab.github.io from the repo `albashaer-hijab/albashaer-hijab.github.io` (git remote `origin`; `old-origin` is the earlier personal repo `Anas-Ammacha/albashaer`, no longer the deploy target). Vercel was not an option: it requires a phone number the owner can't provide). `.github/workflows/deploy.yml` builds on every push to `main` with `GITHUB_PAGES=true` and `NEXT_PUBLIC_BASE_PATH` (from `actions/configure-pages`, e.g. `/albashaer`, empty with a custom domain) and publishes `out/`. In that mode `next.config.ts` switches to `output: "export"`, `trailingSlash`, `images.unoptimized`, and turns off `cacheComponents` / `partialPrefetching` (export fails with "PPR cannot be enabled in export mode" otherwise). Consequences:

- The site must stay fully static: no route handlers, server actions, cookies/headers or other server-only features.
- `basePath` is not applied to `next/image` string sources: wrap every `/images/...` path in `asset()` from `lib/site.ts`. `next/link` hrefs are prefixed automatically.
- To test locally: set both env vars, run `npm run build`, inspect `out/` (stop the dev server first).

## Architecture

- **Tailwind 4 is CSS-first: there is no `tailwind.config`.** Theme tokens live in `app/globals.css`: brand colors are CSS variables (`--brand-*`) under `:root`, mapped to utilities in an `@theme inline` block: `primary` (royal purple), `primary-dark` (near-black, used for top bar / footer / CTA), `secondary` (antique gold), `secondary-deep` (dark gold for small text on light backgrounds), `secondary-light` (gold text on dark), `secondary-soft`, `sand` (alternate section background), `line` (hairline borders), `background`, `foreground`. Change the palette by editing the `:root` values only.
- **Tailwind is wired through Turbopack in `next.config.ts`** (`turbopack.rules` with the `@tailwindcss/turbopack` loader); there is no `postcss.config`. Edit `next.config.ts` by merging into it, never overwrite it: losing that block makes `@theme` fail to parse and the whole site renders unstyled. The same file enables `cacheComponents` and `partialPrefetching`, and allowlists `images.unsplash.com` for `next/image`.
- **Look:** light, editorial, classical. Sections are white / `bg-sand` with `border-line` hairlines; cards are white with a hairline border (no heavy shadows at rest). `.bg-soft` (unlayered, in `globals.css`) is the pale gradient used by the hero, `PageBanner` and the 404 page; don't combine it with Tailwind `bg-*` utilities. Dark is reserved for `Footer`, `CallToAction` and the values card in `AboutSummary`. The owner rejected photo/pattern backgrounds twice: don't put images or repeating patterns behind text.
- **Fonts:** Tajawal (`--font-tajawal`, body) and El Messiri (`--font-display-ar`, headings via the `font-display` utility), both through `next/font` in `app/layout.tsx`.
- **RTL/Arabic:** `app/layout.tsx` sets `lang="ar" dir="rtl"` and renders `ScrollProgress` / `Header` / `{children}` / `Footer` (the owner removed the top info bar; don't re-add one). Phone numbers and handles must use `dir="ltr"`. Use logical utilities (`start-*`, `end-*`, `ms-*`, `text-start`).
- **Single source of content:** `lib/site.ts` holds `siteConfig` (name, slogan, address, `workingHours`, WhatsApp and Instagram URLs), `instagramHandle` (derived from the URL), `phones[]` (the `whatsapp: true` entry links to `wa.me`), `navLinks` and `heroImages`. Update content there, not in components. `README.md` documents the owner workflow (replace logo / hero photos / countries / hours); keep it in sync.
- **Components:** `components/` holds shared pieces: `Header` (client: mobile menu, active link, CTA button), `Footer`, `PageBanner` (breadcrumb + title), `SectionHeading` (`eyebrow`, `align`, `light`), `CallToAction` (closing dark band, used on home and about), `ContactCard`, `Button` (`next/link`-based; `primary` / `secondary` (gold, for dark backgrounds) / `outline`), `icons.tsx` (inline SVG set, no icon library). `components/home/` holds home sections (`Hero`, `TrustStrip`, `AboutSummary`, `WhyUs`, `HowToOrder`); `app/page.tsx` only composes them.
- **No products anywhere:** the owner removed the products page, product data and the colors strip. The home page shows two lifestyle photos in arched frames inside the hero (`public/images/lifestyle/hijab-gold.jpg` and `hijab-calm.jpg`, the owner's own photos). Old product photos remain unused in `public/images/products/`.
- The logo is `public/images/logo.png` (sizing in `components/Logo.tsx`; the `Image` is `unoptimized` so overwriting the file takes effect immediately). `public/images/about.jpg` is the company brochure shown on the about page.

## Animations

No animation library. Keyframes and helper classes (`animate-fade-up`, `animate-pulse-ring`, `btn-shine`, `.reveal`, `.word-reveal`, `.line-grow`) are plain CSS in `app/globals.css`, with a `prefers-reduced-motion` override. Scroll-in effects go through `components/Reveal.tsx` (IntersectionObserver client wrapper; `delay` staggers grids). Wrap new sections in `Reveal` or use `SectionHeading`, which already does. Other motion pieces (client components): `TextReveal` (word-by-word), `Typewriter` (hero rotating words, on its own fixed-height line to avoid layout shift), `ScrollProgress` (top bar).

Keep motion calm: the owner got dizzy from slowly moving background shapes, so no floating/looping decorative elements. Don't put a gradient `background-clip: text` on a parent whose children animate (it caused a rendering glitch in headings).

## Conventions

- All user-facing copy is Arabic, formal, addressing the customer in the feminine (e.g. "تواصلي معنا").
- **Trust content must be factual.** Don't invent years of experience, customer counts or testimonials (the owner removed a stats block). Facts in use: made in Damascus, wholesale, ships inside and outside Syria (never name specific countries: the owner had them removed), all colors available, working hours, and "نموذج مسجّل لدى حماية الملكية" (printed on the company brochure).
- WhatsApp appears only on the contact page and in the footer by the owner's choice: no floating button, no WhatsApp buttons elsewhere. Other CTAs link to `/contact`.
- The contact page has no form and no address card by design (the address is in the footer).
- Keep the footer compact; the owner asked to shrink it more than once.
- Avoid adding UI libraries.
- Source files contain Arabic UTF-8. On Windows, don't rewrite them with PowerShell 5.1 `Get-Content`/`Set-Content` pipelines (it double-encodes them into mojibake); use the Edit/Write tools.
